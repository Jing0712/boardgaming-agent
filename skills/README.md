# 按游戏类型的主持要点（六选一，固定文件）

这个目录跟 `rules/`、`party-content/` 是同一套模式，区别是不需要 `manifest.json`——因为分类只有固定的 6 种（跟首页地图上的六个类型一一对应），文件名直接就是类型 key：

| 文件 | 对应类型 |
|---|---|
| `american.md` | 美式桌游（剧情·战斗） |
| `german.md` | 德式桌游（策略·经营） |
| `wool.md` | 毛线桌游（简单·聚会） |
| `trpg.md` | 跑团（角色·剧情） |
| `wargame.md` | 战棋（战术·推演） |
| `tcg.md` | TCG（卡牌·对战） |

游戏属于哪个类型，是开局时**在代码里确定性算出来的**（扫一遍 `index.html` 里 `GENRES` 目录、看游戏名落在哪个类型的 `examples[]` 里），不依赖模型自己判断或调用工具去读文件——这样不管哪个用户、走哪个入口开局，同一款游戏拿到的这层内容都是完全一样的。玩家手打一个不在收录列表里的游戏名时，这一层就是空的，不影响其他内容源。

## 内容建议

- 这里写的是"这一类桌游主持时容易踩的坑"，不是重复 `buildModeSection()` 已经讲过的"该介入到哪一步"（那是按主持模式分的，跟这里按游戏类型分是两个维度）。
- 几段话就够，不需要长篇大论——参考 `index.html` 里 `buildModeSection()` 每种模式的现有文案量级。
- 跟 `rules/README.md` 一样：这里写的是主持建议本身，不是抄录任何具体游戏的规则书内容。
